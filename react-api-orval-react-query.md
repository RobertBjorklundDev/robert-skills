# React server state with orval and React Query

Regeneration and merge rules for the spec and client are in `backend-ts-openapi-client`.

## Rules
- All API calls use the hooks orval generates (`useGetProject`, `useUpdateProject`, ...) in `app/api/generated/`. Never hand-write `fetch`/axios calls for endpoints in the spec.
- Never edit generated files. If the client is wrong, fix the API or the spec, then regenerate.
- Server data lives in the React Query cache only. Do not copy it into `useState` or Zustand; derive what you need from the query result.
- After a mutation, invalidate the affected queries with the generated query key getters (`getGetProjectQueryKey(id)`), or with orval's `mutationInvalidates` config. Never write query keys by hand.
- Feature-specific wrappers (shared query options, `select` mapping, invalidation after a mutation) live in the feature's `api/` folder.
- Handle loading and error states for every query the user waits on.

## Config

```ts
// orval.config.ts
import { defineConfig } from 'orval';

// orval requires a default export for its config file.
export default defineConfig({
  api: {
    input: { target: '../api/openapi.json' },
    output: {
      mode: 'tags-split',
      target: 'app/api/generated',
      schemas: 'app/api/generated/model',
      client: 'react-query',
      override: { query: { version: 5 } },
    },
  },
});
```

Set `query.version` explicitly so orval generates TanStack Query v5 hooks even when it cannot detect the version from `package.json`.

## Example

Bad:

```tsx
const [project, setProject] = useState<Project | null>(null);

useEffect(() => {
  fetch(`/api/projects/${projectId}`).then((response) => response.json()).then(setProject);
}, [projectId]);
```

Good:

```tsx
const { data: project, isPending, error } = useGetProject(projectId);
```
