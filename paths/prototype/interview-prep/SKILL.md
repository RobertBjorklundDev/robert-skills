# Interview prep after a case

Robert often delegates part of the review to agents during the build, so before the interview he must learn the code he did not read closely.

## Produce
- **Code walkthrough** as text: entry points, request flow, where the important logic lives, and a "files to read first" list.
- **Rule-to-test map:** test names per requirement, so he can open them on request.
- **Weak spots report:** what a code reviewer would comment on, weak tests, inconsistencies between docs and code, things he may not have thought of.
- **Critique list:** what interviewers might ask, alternative tools or designs that might have been better, common industry practice he may not know (e.g. shadow mode before real users see AI output).
- **Architecture diagram** he can talk over.
- **Behavioural prep** if the format is competency-based: concrete situations told as background, action and why, result.

## Rules
- Explain in plain terms when he asks what a line or term means; point to an official doc to read.
- The goal is a conversation, not a defence: accept fair critique and say what you would change.
